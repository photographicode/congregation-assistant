# Mobile usability and notification delivery — 4 October 2026

The scheduling interface has one Review & publish entry point, one auto-assign action, a publish button after the schedule review, persistent publishing feedback, and a direct link to open the published schedule. Messages was removed. Qualifications are collapsed inside person editing. Assignment selection shows the last earlier week for the same assignment role and orders people who have waited longer first, after avoiding another assignment in the selected week. History comes from this device's saved drafts; it is not a record of confirmed attendance or completed assignments.

Unassigned field-ministry slots are excluded from the live schedule. The hidden attendance PDF frames no longer override their hidden display. Home is first on mobile, and Home wording is consistent. Controls and mobile form text are larger. The Superadmin workspace uses a restrained dark and gold presentation.

App installation guidance covers Android and iOS/iPadOS. Menu → Notification settings works even when the app is already installed. Device permission, settings guidance and a local test notification are available. The service worker can receive push events and open the app when tapped, but remote delivery is NOT configured: there is no subscription registration API, subscription storage, VAPID signing configuration, or authenticated server sender. Superadmin notices remain in-app announcements. Do not call them remote push notifications.

The new Supabase project is ACTIVE_HEALTHY with RLS on all ten application tables. Anonymous access to the congregation table is denied and the public schedule RPC is reachable. Security advisors report deliberate privileged functions that require continued review. Google OAuth remains disabled. The live root app still selects the legacy project, which failed the deployment workflow's connection check. The separate staging deployment selects the reviewed new project. Activating that project requires configured Google OAuth, real sign-in verification and migration/backup of any existing records. Frontend deployment cannot resolve those backend prerequisites.

Both GitHub Pages repositories are connected and the public website is deployed. No custom domain was supplied in this conversation. Never put OAuth client secrets, VAPID private keys or service-role keys in public app configuration.
