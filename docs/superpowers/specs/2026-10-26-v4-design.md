# V4: a publisher-first congregation workspace

## Authority and intent
The owner approved the direction and requested immediate implementation and deployment after the single batched questionnaire. Their answers supersede V3 feature/design freezes. Priority: Publishers > Department Overseers > Main Admin. Native execution in this session; no extra approval round. No new paid services. GoDaddy and domain activation are deferred by the owner.

## Experience
Publisher Today contains upcoming assignments, published meetings, announcements and monthly report access. Publishers can edit phone/address/emergency contacts; changes create an in-app Main Admin notification atomically. They can add/remove time-away ranges without approval. No assignment-change request feature. Retain Google approved-account sign-in, roles, departments, reports/households, PDFs, duties, imports/exports, backup, owner/subscription tools and all existing routes.

Use a calm editorial interface with warm neutral surfaces, teal accents, legible sans-serif typography, consistent spacing and clear section titles. Phone navigation prioritizes Today, Meetings, Reports and More. Reduce stacked chrome, empty inspectors and first-visit appearance prompts. English is the launch interface; retain translation resources and document-language handling for future use. Retain other appearance settings without blocking first use. Redesign the public website with the same visual language, publisher-first messaging and a working publisher demo link; no unverified security, email or delivery claims.

## Approaches
A clean-slate backend rewrite increases parity risk; a CSS-only refresh leaves missing workflows. Selected engineering recommendation: retain React/Vite, domain packages, scoped Supabase RPCs and measured PDF engine, replace the shell and publisher experience, and incrementally simplify existing administrator screens. This follows the owner's instruction to use the recommendations and execute.

## Architecture and acceptance
Use existing get_my_publisher_portal, update_my_publisher_contact and save_my_publisher_away. Add a private append-only contact-change inbox via trigger, role-checked admin RPCs and an announcements table/RPC with admin-only writes and approved-member reads. Never expose private tables directly. Query keys include account and congregation. Do not send demo traffic to Supabase. Validate save failures, concurrent edits, empty/loading states, date ranges and sign-out isolation.

Use the existing Pages deployment at its current URL. Prepare same-origin congregationassistant.com/app packaging without activating DNS. Keep bundled /app for same-origin hosting and retain cross-origin redirect compatibility. Test packaging, unit/domain tests, type/lint gates, build, bundle safety, affected browser paths, PDF contracts and CI. Source/publishing and database migrations are separate. Do not delete records simply to make tests pass. Owner states existing records are fictional and authorizes erasure, but no erasure is necessary for this release.

## Limits and delivery
No email or push delivery is promised; notifications are in-app. No GoDaddy sign-in or domain activation now. Preserve immutable v1-final and PDF templates. Use additive schema and down scripts, verify isolated DB tests twice before applying. Report real release blockers rather than weakening gates or claiming deployment without observing it.
