# ADR-001: opt-in device encryption

Status: foundation implemented; Private-mode release protocol incomplete.

Use libsodium-wrappers-sumo, pinned, with XChaCha20-Poly1305 for records, X25519 sealed boxes for scope keys, Ed25519 signatures for identities and Argon2id for encrypted recovery backups. AAD uses a canonical JSON array of congregation, scope, kind, record ID, epoch, revision and schema version, avoiding delimiter collisions. Record keys/nonces are random; revision replay checks are explicit.

Crypto operations have a dedicated worker entry. Device identities can be stored in IndexedDB encrypted under a non-extractable WebCrypto AES-GCM wrapping key, bound to the account. No private key is deliberately stored in localStorage. Runtime JavaScript memory and compromised devices remain outside that storage protection.

MLS is deferred: it adds group protocol/state overhead for small congregation admin sets. Revisit for larger groups, interoperable clients or formal membership/key-transparency requirements. This decision does not justify inventing a replacement ratchet protocol.

The implemented functions compose primitives but do not complete authorization, key authenticity, recovery ceremony, role envelopes or migration. In particular: public-key countersigning/pinning, safety-code verification, custodian recovery, device approval/revocation and epoch rotation remain unfinished. There is no production `privacy_mode=private` enable RPC. `E2EE_CLAIMS_ENABLED=false` and the capability RPC returns private=false.

The current standard app is not called Standard+: server-managed field encryption is still pending. Device local encryption experiments in the old tree also do not establish end-to-end protection.
