# Five-person usability session

Use fictional records in the owner review link, never production data. Recruit five people with different device familiarity. Explain that the software is being tested, not their ability. Ask them to think aloud; do not coach unless they are blocked for two minutes. Record assistance separately from completion.

| Task | Start / success | Target |
|---|---|---|
| Add a publisher with email | People → saved publisher and email | 2 minutes, 4/5 unassisted |
| Assign a midweek part | Schedule → saved named assignment | 2 minutes, 4/5 unassisted |
| Add a visiting speaker | Weekend → saved visitor name and congregation | 2 minutes, 4/5 unassisted |
| Publish and share | Review publication → user-initiated WhatsApp share | 3 minutes, 4/5 unassisted |
| Report for a household member | Publisher demo → correct member, saved report | 2 minutes, 4/5 unassisted |
| Download S-21 | Print & PDF → checked preview and downloaded PDF | 2 minutes, 5/5 unassisted |

These are goals, not results. Do not count an unavailable real backend flow as completed because a demo looks correct. Stop if the participant starts entering real information. Use at most ten combined contact-sheet images; logs and notes are the main evidence.

After tasks, collect the standard ten System Usability Scale statements on a 1–5 agreement scale. Calculate SUS using odd responses minus 1, 5 minus even responses, total × 2.5. Goal: SUS ≥80. Record task success, median time, mistakes, assistance and participants’ actual words. Fix the three most common blockers and repeat affected tasks.
