# RPC matrix contract

This is **isolated PostgreSQL fixture evidence**, not a production audit or a penetration test. `scripts/check-rpc-role-matrix.mjs` runs only against named localhost/container acceptance databases and checks the fictional a/b tenants before inserting fixture identities.

All 106 public signatures are inventoried in `scripts/rpc-access-manifest.json`. The manifest fixes anonymous/authenticated/service execute grants and requires a fixed definer search_path. New functions or changed grants fail pending review. There are 13 intended anonymous RPCs and five service-only worker APIs; internal helper/legacy publication APIs do not inherit authenticated execution.

The 16 caller contexts include anonymous, unapproved Google account, non-Google identity using the owner's email, each of the ten role presets approved in the other tenant, household reporting in the other tenant, global SuperAdmin and service worker. Before cross-tenant cases, every preset is proven authorized in its own tenant. The household fixture has its own approved report-access row. Calls target the real fictional tenant-a publisher/group/link rather than non-existent tenant ids.

Every call executes in a subtransaction forced to roll back, including successful calls; the outer transaction resets role/JWT state. Request values, response data and bearer material are not persisted to the report. Temporary fixture identities/links are cleaned up. Public-link cases use invalid bearer text and must return empty or a uniform denial/validation error; existing acceptance SQL separately exercises valid public/family/group flows. Private/scoped RPCs require denial for unauthorized caller contexts. SuperAdmin scope restrictions are explicit: direct congregation identity, actor-bound Undo actions, assigned publisher attendance and group scope are not replaced by global authority. Other authorized SuperAdmin fixtures permit successful calls or documented input/concurrency validation errors. Service APIs must execute successfully as service_role and remain unavailable to client roles.

Result: **1,696 / 1,696** cases passed, zero failures. The complete per-function/caller outcome is uploaded by CI as `rpc-role-matrix`; committed summary is `docs/qa/launch/rpc-role-matrix-summary.json`. The existing complete SQL acceptance suite supplies positive same-tenant and payload/concurrency tests; this matrix does not claim exhaustive valid-payload branch coverage. Supabase Auth is emulated by fixture auth helpers/tables, so OAuth signatures, provider configuration and production roles require separate owner evidence.
