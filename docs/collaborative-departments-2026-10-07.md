# Collaborative departments release

Attendant, Audio Video and Cleaning have separate workspaces. Main administrators grant Google-account department roles in account access. Department overseers request eligibility from the congregation publisher list; only a main administrator approves or declines. Eligibility approval is separate from account access. Attendant attendance counting remains separate from assigning attendant duties.

Departments configure duty names and one to four people per duty. Choose week, choose approved people, save assignments. OCLM receives these duties at the bottom for review and publication through the existing publisher link. Saving a department draft does not publish it. Existing published weeks, other assignments, and cloud revision checks remain in place. Existing departmental qualifications/assignments are retained and adopted as pending approval; administrators should approve the intended people before new assignments. Reducing duty capacity cannot discard existing assignments.

Server checks restrict department edits, publisher scope, approval decisions, availability, shared revision conflicts and full-backup recovery. Direct private-table access is denied. Department roles do not gain publisher contact or report access. An administrator can retain both existing roles and the new department roles as needed.

Large-text screens use wrapping full-width names, search, optional assignment settings and comfortable controls. CSV import previews additions/updates before writing and retains the file after failure. Import contacts before reports in the same session to match exported identifiers. Full restore opens a summary, downloads an encrypted safety copy, and requires confirmation before replacement. Administrator and department account access, billing and live-link tokens remain in place. Personal publisher access is removed for records omitted from the backup and must be approved again if those records are later recovered.

The sample congregation is isolated in per-tab browser storage. Each new entry resets 12 fictional publishers, three groups, current/prior service-year reports and a short optional tour. It does not submit publisher data, send notifications or create real public links. Reload resumes the current sample session.

Validation: existing application, cloud-conflict and encrypted-backup regression checks; isolated PostgreSQL 17 approval/isolation/revocation/publication/restore checks; browser role and rejected-save/import recovery checks at 320, 390 and 1440 pixels with 100% and 200% text; accessibility checks across seven themes; illustrated website image and reflow checks. CI runs Chromium and WebKit. Exact production files are checked after Pages deployment.

Human acceptance still needed: a Realme 12 with the actual maximum font/display settings, iPhone text enlargement, and younger/older congregation users completing the core tasks. Automated text scaling does not establish every physical-device setting.

Delivery services remain prepared rather than advertised as activated. Privacy/Terms drafts remain unpublished pending the requested wording changes. No paid service, provider migration or congregation-data reset is part of this release.
