## 0. Engineering rules (put these verbatim in `AGENTS.md`; they exist to stop vibe-coding)
1. **Think before coding.** State the assumption and the success check before you change code; if two readings exist, pick one, write it in `docs/DECISIONS.md`, move on.
2. **Simplicity first.** The smallest change that solves the problem; no speculative abstractions, flags or "future" code.
3. **Surgical changes.** Touch only what the task needs; match the surrounding style; do not reformat unrelated code.
4. **Goal-driven, verified.** Write the failing test or measurable check first; do not say "done" until the check ran green; show the command and result in `docs/POLISH-REPORT.md`.
5. **Systematic debugging.** Reproduce → isolate → fix root cause → add a regression test. No retry-until-green; a fix that fails twice is logged and escalated.
6. **Evidence over claims.** Every ✔ in `CHECKLISTS.md` links to a test, script or document. Unverified = say so.

Create `scripts/site-audit.mjs` (run in CI against `dist/site`, plus a Playwright pass at 320 / 390 / 768 / 1440 px). **HARD = zero failures** for every item the owner listed:
| Owner item | Rule the audit enforces |
|---|---|

| Find broken links | crawl every internal `href/src` (all 13 locales × all slugs, anchors, assets); external links HEAD-checked in the weekly job, never failing PRs; root-absolute links must work under the Pages base path |
| Add a mobile menu | below 768 px the nav collapses to a labelled button (`aria-expanded`, `aria-controls`, Esc closes, focus trap, 44 px targets) |

| Fix page titles / meta descriptions | unique `<title>` (≤ 60 chars) and `<meta description>` (70–160) per page **per locale**; one `<h1>`; `canonical`; `hreflang` for all 13 locales; Open Graph + Twitter tags with `og:image` (1200×630, generated) |
| Footer links / unused navigation / logo | every footer and nav link resolves and is used; logo links to the localized home; no dead items |
| Custom 404 | `404.html` is branded, localized, offers Home/Search, and returns HTTP 404 on Pages (test with an unknown URL) |
| Copyright year | footer shows © + the current year, driven at build time (no hard-coded year); test fails if year ≠ build year |
| Clickable phone / email | every email is a `mailto:` link; any phone is `tel:` (E.164); **no unlinked emails**; support address only `support@congregationassistant.com` (no personal Gmail) |

| Fix broken buttons | every `<button>` has `type`; every button/link has an action; no `href="#"` |
| Success / error messages | the request/contact form shows inline field errors, a success state and a failure state with retry (`role="status"`/`role="alert"`), keeps typed input, protected by Turnstile + server rate limit; test all three states |
| Remove placeholder text | build fails on `lorem`, `TODO`, `example.com`, `{{…}}`, `your-…`, `coming soon` (unless flag-gated), empty `trust.json`/`about.json` values (render the neutral fallback instead) |
| Mobile optimized pages | viewport meta on **every** page (the guide has none), tap targets ≥ 44 px, font ≥ 16 px for inputs, Lighthouse mobile ≥ 95, no layout shift |

## 3. SECURITY AUDIT — findings from the code and the exact fixes
**Already good (keep, add tests):** no secrets in the tree (publishable/anon key is public by design); `.env*`/`*.pem`/`*.key` ignored; the only env use is `BASE_URL`; no sourcemap setting (Vite default = none — verify no `.map` in output); Pages publishes only `dist-site` + `dist` (no `docs/`, `supabase/`, `tests/`); no `eval`/`innerHTML`/`dangerouslySetInnerHTML`; strong CSP, HSTS, nosniff, Permissions-Policy in the worker; `localStorage` holds preferences only; no wildcard CORS found.
**Fix now:**
1. **Legacy password schema.** `supabase/fresh-project.sql` still defines `congregations.admin_password text` and `group_access` password columns; `ca_private.owner_bootstrap.password_digest` exists. Run `select table_schema, table_name, column_name from information_schema.columns where column_name ilike '%password%';` on the **production** project (read-only) and record the result. Write a migration that **drops** every legacy password column/table no longer used (`down` restores structure only), delete these from `fresh-project.sql`, and add `scripts/check-no-password-columns.sql` to CI. (We do not store passwords; there is nothing to hash — Google sign-in/magic link only. If any plaintext value exists, record the count, rotate/force re-auth, then drop.)
2. **Retired edge function** `supabase/functions/owner-password-session` (returns 410): delete it from the repo and **undeploy** it in Supabase (OWNER dashboard step in `OWNER-TODO.md`); its CORS origin is hard-coded to `photographicode.github.io` — move all remaining functions to the config allow-list (`https://congregationassistant.com`, `https://app.congregationassistant.com`, GitHub Pages fallback) with exact-origin matching.
3. **Form sanitisation.** `maxLength`/`min`/`max`/`pattern` are almost absent (0 in `PublicForm.tsx` and `PublisherEditor.tsx`, 1 in `Reports.tsx`). Add limits to **every** input (names 120, notes/comments 500, phone 20, email 254, numbers with ranges: hours 0–744 step 0.25, studies 0–99), validate with **Zod** shared between client and the SQL function checks (length/range inside each RPC), and add tests with oversized, empty, Unicode, zero-width and script payloads. Output stays React-escaped; PDFs and CSV exports escape too (formula-injection neutraliser).
4. **Rate limiting.** No named rate-limit function was found in the SQL. Implement `ca_rate_limit(key, limit, window)` + table (hashed IP/token keys, TTL cleanup) and call it from **every** anonymous RPC (application form, public report/attendance, noticeboard, link exchange); Turnstile on the application form; uniform error text; tests that the 11th request in a window is rejected and that two different tokens don't share a bucket.
5. **Admin routes.** Owner/admin visibility is derived in the client (`owner` state) — the server must be the authority. Add tests: for **every owner/admin RPC**, a non-owner/non-admin/other-tenant call fails; the `?demo=owner` path never calls a real RPC and never shows real data (assert zero requests in demo mode). Keep the role × function matrix from the quality orders.
6. **Database:** RLS enabled + forced on every exposed table (9 tables lack an explicit `enable`/policy: `ca_private`, `ca_migrations`, `ca_ap_private`, `ca_oclm_*`, `ca_meeting_*` — enable or move to a non-exposed schema), default-revoke function privileges and grant from a manifest, Supabase advisors reduced to documented exceptions (`V3-QUALITY-ORDERS.md` §7).
7. **Exposed files:** add `scripts/check-published-files.mjs` that scans `work/pages` before deploy and **fails** on `*.map`, `.env*`, `*.sql`, `*.md` (except intended), `.git*`, `*.bak`, `*.zip`, `docs/`, `supabase/`, `tests/`, `node_modules/`, any file > 5 MB, and secret patterns (`service_role`, `sb_secret_`, `rzp_live_`, private-key headers, JWT-looking strings other than the publishable key).
8. **Git history:** this review had no `.git`; run `gitleaks detect --log-opts="--all"` and `trufflehog git file://. --only-verified` in `security.yml` on every push and once on the full history now; report counts. If anything real appears: list it for rotation (OWNER), do not rewrite history unless asked.
